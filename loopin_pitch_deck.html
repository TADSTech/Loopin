The Pain Point

Manual scheduling is chaos.

Life is images and conversations — but calendars only accept structured data.

⌨️ 01 · Friction

Too much typing

Opening the calendar, toggling dates, fixing timezones, pasting addresses, and typing titles takes about two minutes per event.

🕳️ 02 · Missed

Missed opportunities

Because typing it in is tedious, people defer it. Screenshots get buried in galleries — hackathons, meetups, and webinars get missed.

🗂️ 03 · Chaos

Unstructured text

Flyer copy and chat notes are messy: vague phrases like “this coming Wednesday”, mixed time formats, and long address directions.

The Engine Under The Hood

How we built it.

A modern web stack built for speed and constrained security.

▲
Next.js 16 + React 19
Core framework

App Router with Server Actions for zero client-bundle bloat and instant form mutations.

◉
Groq + OpenAI SDK
Multimodal AI

Low-latency Llama vision models on Groq endpoints finish extraction in under a second.

⬡
Supabase Backend
Database + OAuth

Postgres with Row Level Security (RLS) and Google OAuth token refresh handled server-side.

◆
Zod Schema Guard
Data integrity

Runtime validation keeps AI responses inside the structured calendar payload spec.

⚡
Bun Runtime
Tooling + tests

Fast Bun runtime runs the unit tests and pre-commit hooks before each release.

▦
Tailwind CSS v4
System design

Calm, high-contrast layout with container queries and light/dark theme switching.
